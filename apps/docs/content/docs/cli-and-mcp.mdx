The `openmail` command line tool and the MCP server read the same local database as the desktop app. They do not start the app.

## Install the command

The CLI comes with the OpenMail source. After building it, link the command globally:

```sh
pnpm --dir packages/cli link --global
```

## Common commands

```sh
openmail accounts list
openmail sync
openmail list --mailbox inbox --unread
openmail list --space <space-id> --json
openmail search 'from:billing has:attachment'
openmail search 'invoice' --server --json
openmail show '<message-id>' --thread
openmail spaces list
openmail health --json
openmail tools --json
```

`list` and `search` print one line per conversation: date, sender, subject and the message id that `openmail show` takes. Unread conversations have a `*`. When there are more, the last line gives the `--cursor` for the next page. Add `--json` for the machine format: `{"threads": [...], "next_cursor": "..."}`.

Spaces group accounts, such as Work and Personal. `openmail spaces` manages them and `--space` filters `list`. The older `openmail profiles` and `--profile` still work.

The CLI has no send command. Sending happens in the app.

### Commands you type and agent tools

`list`, `search`, `show`, `sync` and `health` are commands you type, so they run as you. They read every account that is turned on in OpenMail, like the app does. They do not check **Allow AI to read this account**: a command in your own shell could read the database file anyway, so that switch would protect nothing there.

`openmail tool <name>` runs an agent tool exactly as an MCP client would: same consent checks, parameters and results. Use it to test what an AI app will see, or in scripts that act for a model. `openmail tools --json` lists every tool with its input schema, and `openmail tool --help` lists them by name.

```sh
openmail tool access_status --json
openmail tool read_thread --input-json '{"id":"gmail:me@example.com/m1"}' --json
openmail tool draft_message --allow-writes --input-json '{"account_id":"gmail:me@example.com","to":["alice@example.com"],"subject":"Status","body":"Tomorrow.","rationale":"Draft for review."}' --json
```

`--allow-writes` exists only on the proposal tools. Where an MCP client gets an empty result because no account allows AI reads, `openmail tool` prints an error on stderr and exits with code 1:

```text
error: No accounts allow agent reads. Turn on 'Allow AI to read this account' in Settings → AI Access.
error: Account gmail:me@example.com does not allow agent reads. Turn on 'Allow AI to read this account' in Settings → AI Access.
error: No account with id gmail:typo@example.com. Run `openmail accounts list` to see them.
```

A tool that fails prints its message the same way. With `--json`, the CLI also prints `{"message": "...", "code": "...", "hint": "..."}` on stdout, the same object an MCP client gets.

## Connect from the app

Open **Settings → AI Access** and scroll to **AI apps**. OpenMail shows a card for Claude Code, Codex, Claude and Cursor. Each card says whether the app is installed, whether it is connected to this copy of OpenMail, and which tools it called recently.

Click **Connect** to add OpenMail's MCP server to the app. Before anything changes, OpenMail shows the command it will run and a diff of the config file. Nothing happens until you confirm.

- **Claude Code**: OpenMail runs `claude mcp add-json --scope user`. The server is available in every project. To reconnect, it removes the old entry and adds the new one. If the add fails, it puts the old entry back.
- **Codex**: OpenMail runs `codex mcp add` to connect and `codex mcp remove` to disconnect. To reconnect, or without the `codex` command, it edits `~/.codex/config.toml` directly.
- **Claude** and **Cursor**: OpenMail edits `claude_desktop_config.json` or `~/.cursor/mcp.json`.

OpenMail changes only the `openmail` entry. A reconnect changes only its command, arguments and `OPENMAIL_HOME`, so keys you added yourself, such as `disabled` or `startup_timeout_sec`, stay. When OpenMail edits a file itself, it saves a backup next to it first. It never writes tokens or passwords into another app's config. If the file can't be read, OpenMail refuses and changes nothing.

A connected app is read-only. In the confirmation, check **Let … make AI suggestions for you to approve** to add the [write tools](#ai-suggestions). If a card says **Points at another OpenMail copy**, the entry points to another copy of the app, for example one you ran from a disk image. Click **Reconnect**.

Restart the app or start a new session after connecting. Claude must be quit and reopened.

The **Accounts AI apps can read** row above the cards shows which accounts every connected app sees. If no account allows AI reads, a connected app gets empty results.

## Connect by hand

Each card's **Set up by hand** section has the exact command or JSON for your Mac. The server command is:

- A packaged app: `/Applications/OpenMail.app/Contents/MacOS/OpenMail --mcp`
- The CLI from source: `openmail mcp` after you [link the command](#install-the-command), or `node /absolute/path/to/openmail/packages/cli/dist/cli.js mcp`. Use an absolute path, because MCP clients start the server from their own working directory.

Add `--allow-writes` for the [write tools](#ai-suggestions).

Claude Code:

```sh
claude mcp add --scope user --transport stdio openmail -- /Applications/OpenMail.app/Contents/MacOS/OpenMail --mcp
```

Codex:

```sh
codex mcp add openmail -- /Applications/OpenMail.app/Contents/MacOS/OpenMail --mcp
```

or in `~/.codex/config.toml`:

```toml
[mcp_servers.openmail]
command = "/Applications/OpenMail.app/Contents/MacOS/OpenMail"
args = ["--mcp"]
```

Claude (`~/Library/Application Support/Claude/claude_desktop_config.json`) and Cursor (`~/.cursor/mcp.json`):

```json
{
  "mcpServers": {
    "openmail": {
      "command": "/Applications/OpenMail.app/Contents/MacOS/OpenMail",
      "args": ["--mcp"]
    }
  }
}
```

With the CLI from source, use `"command": "openmail"` and `"args": ["mcp"]`. If the app cannot find the command, use the full path printed by `command -v openmail`.

The server tells the model to start with the `access_status` tool. It lists the accounts the client can read, how many are hidden and why, and what you need to change in the app. It shows only the number of hidden accounts, never their addresses.

## Default tools

The server hides write tools unless you turn them on. `sync` is the one default tool that is not read-only: it pushes changes that you already approved in the app and that are still queued. A [read-only session](#read-only-sessions) blocks that.

By default the server offers 20 tools:

| Tool               | What it does                                                                                 | Read-only |
| ------------------ | -------------------------------------------------------------------------------------------- | --------- |
| `access_status`    | Say which accounts the client can read, why others are hidden and what to change in the app. | Yes       |
| `list_accounts`    | List connected accounts that allow MCP access.                                               | Yes       |
| `list_profiles`    | List spaces, such as Work and Personal. MCP calls them profiles.                             | Yes       |
| `list_labels`      | List labels (Gmail) and folders (Outlook, IMAP) per account.                                 | Yes       |
| `list_threads`     | List conversations in a mailbox, newest first, from the local copy.                          | Yes       |
| `search`           | Search mail with Gmail-style operators.                                                      | Yes       |
| `semantic_search`  | Search by meaning, using the on-device text index. Snippets are omitted.                     | Yes       |
| `read_thread`      | Read a conversation as plain text, oldest message first.                                     | Yes       |
| `sync`             | Fetch new mail from the providers and push changes you already approved in the app.          | No        |
| `list_templates`   | List templates.                                                                              | Yes       |
| `read_template`    | Read a template's subject, recipients and plain-text body.                                   | Yes       |
| `list_signatures`  | List signatures.                                                                             | Yes       |
| `read_signature`   | Read a signature as plain text.                                                              | Yes       |
| `suggest_contacts` | Suggest recipient addresses from local history and cached contacts.                          | Yes       |
| `list_invites`     | Read calendar invitations in a message.                                                      | Yes       |
| `calendar_overlap` | List calendar events that overlap an invitation.                                             | Yes       |
| `list_attachments` | List a message's attachments: name, type and size.                                           | Yes       |
| `attachment_text`  | Read text that on-device OCR or PDF extraction already produced.                             | Yes       |
| `list_proposals`   | List changes that wait for your approval in the app.                                         | Yes       |
| `read_proposal`    | Read one pending proposal.                                                                   | Yes       |

With write access turned on, the server adds 3 write tools:

| Tool             | What it does                                                                                                | Read-only |
| ---------------- | ----------------------------------------------------------------------------------------------------------- | --------- |
| `modify_threads` | Propose archive, read or unread, star or unstar, or adding or removing a label, for up to 20 conversations. | No        |
| `snooze_threads` | Propose snoozing up to 20 conversations.                                                                    | No        |
| `draft_message`  | Propose a new message or reply as a local draft. A reply can omit to and subject.                           | No        |

An MCP client can only read accounts for which you turned on **Allow AI to read this account** in **Settings → AI Access**. OpenMail checks this on every call. Mail reaches the MCP client, and from there the model provider that client uses. Choose clients you trust.

Tool results put all mail content in an `untrusted_mail` field with a notice, so the model treats message text as data, not as instructions. OpenMail's own guidance, such as `access_status` and the message a write tool returns, sits outside that field.

Every key in a result is snake_case, at any depth, like the tool parameters: `account_id`, `is_unread`, `next_cursor`, `needs_reauth`. Fields that would always be empty are left out. `read_proposal` returns the AI suggestion as a `command` object.

A failed call returns `isError` with a `message`, a `code` and a `hint` that names the next step. The codes are `not_found`, `invalid_input`, `no_ai_consent`, `denied`, `not_ready`, `reauth_required`, `provider_rejected`, `provider_unavailable` and `too_many_proposals`. An `account_id`, `profile_id` or other id the client cannot read fails with `not_found`, so a typo never looks like an empty mailbox. `semantic_search` fails with `not_ready` while the on-device index has nothing for the account. Arguments that don't match a tool's input schema come back the same way, with code `invalid_input`, so the model can fix them; they are not JSON-RPC protocol errors. A key the tool does not declare, such as `acount_id`, fails the call and names the closest valid key. A `cursor` that is not the tool's own `next_cursor` fails too; omit `cursor` to start from the first page.

## AI suggestions

A change an agent asks for is an AI suggestion. The tools and the CLI call it a proposal (`list_proposals`, `openmail proposals`). Write tools need two switches:

1. Start the server with `--allow-writes`. In the app, check **Let … make AI suggestions for you to approve** when you connect.
2. Set **Changes by AI apps** in **Settings → AI Access** to **Ask me first**.

If **Changes by AI apps** is **Read only**, a write tool changes nothing. The call fails with code `denied` and tells the model where you can change it.

Even then, the server adds only the write tools listed above. Each call creates an AI suggestion. You review and approve it in the app under **AI suggestions**. Drafts stay on your Mac until you open and save them. Sending always requires you to confirm in the app.

There are no tools for permanent delete, emptying Trash, creating server filters, forwarding settings, account or OAuth changes, or AI settings.

## AI suggestions in the CLI

`openmail proposals list` shows pending AI suggestions, and `openmail proposals reject <id>` rejects one. The CLI cannot approve them: you approve them in the app, under **AI suggestions**. An agent that can run shell commands could otherwise approve its own AI suggestions, so only a click in the app counts as your confirmation.

## Read-only sessions

Set `OPENMAIL_READ_ONLY=1` before starting the CLI or MCP server to block every write to the mail server, including queued changes. Local state can still change, and OpenMail can still read from the network and refresh tokens.

```json
{
  "mcpServers": {
    "openmail": {
      "command": "openmail",
      "args": ["mcp"],
      "env": { "OPENMAIL_READ_ONLY": "1" }
    }
  }
}
```
