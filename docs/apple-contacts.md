# Apple Contacts integration

"Use Apple Contacts" in Settings → Compose is off by default. The app calls `ContactsCLI --request` only when this switch is on. Startup, address suggestions, menus, refresh and photo lookups only check the existing authorization and never show a permission prompt. Denied, restricted by the system and limited access each show their own status, with a link to System Settings.

This page maintains the permission, snapshot and signing rules for Apple Contacts. Module locations are in the [architecture](architecture.md). The data scope of MCP and the built-in assistant is in the [agent guide](agents.md). The general check commands are in [testing](testing.md).

- `ContactsCLI.swift` uses CNContactStore and reads only identifiers, names, email addresses, organizations and contact groups. It requests the thumbnail field only when the photo setting is on. Each photo is capped at 256 KiB, and all thumbnails in one snapshot are capped at 8 MiB.
- Suggestions, groups, photos and menus use the in-memory snapshot right away. In the background the app checks authorization at most once every ten seconds and refreshes the snapshot every minute. A manual refresh starts a background replacement and keeps the old snapshot until it finishes. Turning the switch off, a revocation found by polling, a helper failure or invalid JSON clears the cache. Turning photos off removes thumbnails right away. A late result cannot restore data that was turned off or revoked.
- Each window mounts a contacts status poll. A change in status or snapshot version invalidates `Keys.contacts` and refreshes existing suggestions, groups, photos and contact identifiers. The status query does not register that key, so polling does not recurse.
- If a permission request runs longer than 120 seconds and the timeout kills the process, the app shows "Waiting for Contacts permission. Respond to the system prompt." and does not request again. When a later status poll sees the grant or denial, the UI updates. Other execution errors still show a failure.
- `createAppleContactsCache` is an in-memory component exported by core and used only by the desktop RPC adapter. There is no database table, disk contacts cache, network request, MCP tool or AI context entry for it. Mailbox's server contacts and AI paths do not use this snapshot.
- Address suggestion merging and name priority are in [row C15 of parity](parity.md#撰写). The Apple source uses the in-process cache. Server and mail history sources keep using the Store queries.
- An Apple contact group expands to one email address per person. CNContactStore has no API for the preferred address in a distribution list. With full access, the helper reads the group preference through the public `ABGroup.distributionIdentifier(forProperty:person:)`, falls back to the person's preferred address, then to the first valid address. For group members it requests only identifiers and email addresses. With limited access it uses only contacts visible to CNContactStore and does not access Address Book. Core handles stale preferences and duplicate group members.
- "Open in Contacts" accepts only UUID or UUID:ABPerson identifiers and opens an `addressbook://` URL that keeps the colon. It rejects queries, fragments, paths and other record types. "Add to Contacts" creates a private temporary vCard only after the click and opens the Contacts import confirmation through `/usr/bin/open -b com.apple.AddressBook`. The helper has no CNSaveRequest or other write operation. The temporary file uses the same permissions and cleanup as the attachment temporary directory.

## Packaging and permissions

`build/build-vision.mjs` compiles arm64 and x86_64 and merges them with lipo into `out/native/contacts`. electron-builder copies it to `Contents/Resources/native/contacts` and signs it. `mac.extendInfo` provides `NSContactsUsageDescription`, and InfoPlist.strings for ten languages are copied into the bundle Resources. Chinese ships both `zh_CN.lproj` and `zh-CN.lproj`.

[Apple's contacts entitlement documentation](https://developer.apple.com/documentation/bundleresources/entitlements/com.apple.security.personal-information.addressbook) requires declaring `com.apple.security.personal-information.addressbook` under the Address Book capability of the Hardened Runtime. The main app's signed and ad-hoc entitlements keep this key. The two inherit files for ordinary Electron child processes do not have it. `sign-contacts.cjs` reuses electron-builder's signing options and assigns a separate `entitlements.contacts.plist` only to `Contents/Resources/native/contacts`. Authorization status handling follows [Accessing the contact store](https://developer.apple.com/documentation/contacts/accessing-the-contact-store). For the preferred address in a group, see [ABGroup](https://developer.apple.com/documentation/addressbook/abgroup) and [the Contacts distribution list guide](https://support.apple.com/guide/contacts/edit-distribution-list-lists-smart-adrbk1513/mac).

## Verification limits

Unit tests use fake helper JSON, a fake provider and a fake model. They verify permission gating, the ten-second throttle, slow background reads, invalidation on revocation, off and photo races, history ordering, the group preferred address, strict URLs, the fixed Contacts import, timeout recovery and signing options. The composer AI regression checks the model request after the account opt-in is on and confirms it has no Apple Contacts snapshot fields. The native helper is verified with `--self-test`. That mode checks pure functions and authorization status and does not create a contact store or read contacts. The existing automated checks do not start Electron and do not read a real address book. System authorization, contact card navigation and the import confirmation in a signed build still need acceptance on a real Mac. They are listed in the [roadmap](roadmap.md#owner-to-do). The release build steps are in the [release notes](release.md). No new migration was added, and the OAuth scopes did not change.
