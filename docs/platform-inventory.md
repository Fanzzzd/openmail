# Core platform inventory

Read this before changing a core platform implementation, a package entry or a mobile Layer. The import boundary rules are in AGENTS.md, and `.oxlintrc.json` is the source of truth for banned packages. [platform-imports.test.ts](../scripts/repo-checks/src/platform-imports.test.ts) reads that config. It also checks Node built-in modules, the local dependency graph of the portable entry, and that the top of `src` holds only package entries.

The audit of the original `packages/core/src` covered static, type-only and dynamic imports, plus the `.mjs` workers. Every production Node implementation now lives in `platform/node/`. Process test fixtures, the fake provider and the in-memory SQLite test platform live there too. The "Original file" column below uses the file names at audit time. The parts that stayed in core were later split into domain folders; [ADR 0001](adr/0001-core-layout.md) gives their locations.

The Node-only packages are `@effect/platform-node`, `@effect/platform-node-shared`, `@effect/sql-sqlite-node`, `@napi-rs/keyring`, `sqlite-vec`, `onnxruntime-node`, `imapflow`, `nodemailer`, `mailparser` and `pdfjs-dist`. The Transformers model worker is also confined to the Node adapter. Mobile provides no `ModelRuntime`, so on-device inference is not supported there; the mobile notes give the reason. `better-sqlite3` is on the banned list as well, and the desktop app keeps using `node:sqlite`. imapflow, nodemailer, mailparser and `@effect/ai-anthropic` load through dynamic imports on the first connection, build, parse or AI request, so desktop startup does not load them. A failed import maps to the original operation's error type. semver is imported by function subpath (see [performance notes](performance.md#主进程懒加载与阅读器拆块slice-105)).

Core byte handling is centralized in `platform/bytes.ts`. On Node it uses the native Buffer. When that global is missing, it falls back to the browser implementation in `buffer/index.js`. The import guard checks this module's native Buffer probe; AGENTS.md has the boundary rule. base64url converts the alphabet and padding explicitly. TNEF uses Uint8Array and DataView directly over a shared bounded input. UTF-16LE decoding keeps the BOM and lone surrogates by hand and drops a trailing single byte, which matches native Buffer output. Synchronous SHA-256 and HMAC use the portable `@noble/hashes` implementation. On Node, `PlatformCrypto` uses native crypto. Mobile must provide the random number service with a secure random implementation.

The [roadmap](roadmap.md#core-平台接口) tracks the remaining mobile work. The repo has the Expo project, core op-sqlite, OAuth, provider and MIME adapters with no React Native dependency, and the mobile Expo OS Layers. The [mobile notes](../apps/mobile/README.md) list the entry points. When the portable entry was introduced, it was bundled once for the browser platform; no test repeats that bundle. The import check proves core's local module boundary. It does not replace testing on a real React Native device, verifying Metro bundling of third-party packages, or checking op-sqlite compatibility.

The reader's CSS sanitizer and visible-text extraction import `css-tree/dist/csstree.esm` directly. In css-tree 3.2.1, `exports["./dist/*"]` points to `./dist/*.js`. That entry is the complete browser ESM bundle and does not use the root entry's `module.createRequire`, so it does not depend on Metro redirecting the root entry through its `browser` field. The mobile `metro.config.cjs` uses Expo's default resolver and does not rewrite resolution for this package. `platform/node/css-browser.test.ts` checks the export map, the browser bundle and real CSS parsing. Metro was not run for this check.

`HtmlText` (`platform/html-text.ts`) is the service that turns HTML into text during provider parsing. The portable default runs it on the current thread, and mobile uses that default. `NodePlatform` provides the worker pool in `platform/node/html-text.ts`: max(1, min(2, CPU count − 1)) workers, 2 s per message. A timeout falls back to tag-stripped text. After three failed starts in a row, extraction goes back to the current thread.

MailCodec, PdfWorker, AttachmentFiles and ImageNetwork are required Effect services. A missing Layer is a type error. Providers, reader attachments and the indexer capture their dependencies at build time, and the methods they return do not read the caller's hidden context. Real NodeMailbox regression tests cover the IMAP raw MIME fallback, body, calendar and nested attachments, PDF indexing, the file cache, image input and SSRF rejection. They replace only the IMAP transport and use a synthetic password and a temporary database. They do not start Electron.

Mobile database recovery is in `platform/react-native/database-recovery.ts`. It uses `MobileDatabaseRecovery`, Effect FileSystem, AppPaths, PlatformCrypto and a structured op-sqlite port. The list of user tables is in `platform/recovery-tables.ts`, shared by both platforms. The mobile OS assembly is in `apps/mobile/src/platform/database-recovery.ts`. Foreground and headless databases share one recovery gate. Effect FileSystem persists the result and time of the foreground check, and a cold background start can reuse a success record that has not expired. The SQLite shim lives only in `packages/core/test-support` and is not part of the production build. The [mobile database notes](../apps/mobile/README.md#数据库) cover integrity checks, quarantine, salvage, provider resync and interruption boundaries.

The no-op mobile Layers for `PdfWorker` and `ImageNetwork` are in `platform/react-native/media.ts` and return unavailable explicitly. The existing PDF.js worker does not run on Hermes. Mobile has no fixed-address image import, and fetch cannot stand in for DNS pinning. The reader keeps using shouldLoadRemote and the HTTPS CSP. On-device inference is not implemented. The detailed budgets, security rules and reasons are maintained only in the [mobile media notes](../apps/mobile/README.md#媒体适配边界). These adapters call no Node API, conversion service or cloud media inference.

The portable IMAP and SMTP protocol is in `platform/react-native/`. `imap.ts` assembles the adapter, `imap-session.ts` manages the session, `imap-parse.ts` parses responses, `imap-push.ts` pushes queued operations and `smtp.ts` sends. `MailTransport` exposes only a TCP/TLS byte stream; the native mobile implementation is in `apps/mobile/src/platform/transport.ts`. Both platforms share `providers/imap/imap-settings.ts` to resolve account presets, and passwords still go through Secrets. The Expo attachment cache and temporary share copies live in the mobile sandbox cache. Core's AttachmentFiles still handles capacity, cleanup and version invalidation. No database migration was added. Patches for native TLS certificate hostname checks, Android read-thread synchronization and the handshake-complete event on both platforms install with the pnpm lockfile. The [mobile capability table](../apps/mobile/README.md#能力) lists the capabilities and what has been verified.

Database copying and copy migration for the dev smoke test are in `platform/node/smoke.ts`. The desktop script only calls this core export. Core reads `OPENMAIL_READ_ONLY=1` through Effect Config when it builds the Layer. `mailbox/read-only.ts` and `mailbox/mailbox-live.ts` hold the provider write blocking and the queue and send policy. No implicit Node global is involved.

Shared exports are collected in `common.ts`. The Node entry re-exports only the names the desktop app and CLI use. It does not load mobile adapters or mobile-only workflows through `portable.ts`, and `platform-imports.test.ts` checks that dependency graph. Mobile keeps getting shared capabilities and the mobile platform assembly from `portable.ts`.

Visible-text extraction first parses the reader's sanitized output and the reference shell as HTML5 with parse5 8.0.1. parse5-htmlparser2-tree-adapter 8.0.1 then connects the result to the existing selectors and walkers. Both entries are pure ESM parsing code and call no Node platform services. A regression test checks that table foster-parenting matches browser parsing. This check did not run Electron or Metro.

## IMAP differences between Node and React Native

Read this before changing an IMAP provider or discussing whether the two platforms behave the same. Slice 71 only extracted the identical pure functions and split the Node modules. The nine items below keep their original behavior and need a product decision before they are unified.

| Item                | Node                                                                                     | React Native                                                                                                      |
| ------------------- | ---------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------- |
| Special folders     | Uses the server's special-use flags. Ordinary folders keep their path labels.            | Also matches name aliases such as Sent Items and Deleted Items.                                                   |
| Large messages      | Above 10 MB, reads the first 512 KB and takes attachment info from BODYSTRUCTURE.        | Downloads the whole message and rejects anything above 25 MB. No truncated parsing.                               |
| Flag changes        | With CONDSTORE enabled, uses changedSince and separately checks which UIDs still exist.  | Decides when to scan from capabilities and time, and reads FLAGS for every known UID.                             |
| Search scope        | Compiles the server search criteria, then fetches and rechecks the messages.             | Searches UNDELETED, reads newest first and matches locally, scanning at most 1000 messages.                       |
| Attachment download | Prefers downloading the MIME part named in BODYSTRUCTURE; falls back to the raw message. | Downloads the whole message, then parses it and picks the attachment.                                             |
| Remote drafts       | Supports APPEND, replace, organizing flags, conflicts and retry recovery.                | Drafts stay local. saveDraft and deleteDraft are not supported.                                                   |
| Folder management   | Supports creating, renaming, moving and deleting folders.                                | changeLabel is not supported.                                                                                     |
| Permanent delete    | Requires UIDPLUS or IMAP4rev2, deletes only the target UIDs and returns partial results. | checkPermanentDelete and permanentlyDelete are not supported.                                                     |
| SMTP send           | Uses message.from, reports partial recipient rejections and can create the Sent folder.  | Uses the account address as envelope and MIME sender, handles each RCPT reply, and needs an existing Sent folder. |

Node IMAP is split into `platform/node/imap/{adapter,session,parse,pull,ops,send,recovery,pool}.ts`. Outlook is split into `providers/outlook/{graph,client,sync,parse,pull,recovery,folders}.ts`, with sending further split into `draft-state.ts` (draft creation log and versions), `drafts.ts`, `graph-message.ts` and `send.ts`. The old entries export only the provider assembly functions. Callers import pure functions and transport helpers directly from the module that owns them.

The T07 `CacheStorage` port is in `platform/cache-storage.ts`. The Node implementation in `platform/node/cache-storage.ts` reads the WAL and recovery files through the real database path, and volume space through `statfs`. The portable default returns `disk: null` and zero external file bytes, so mobile does not detect low disk space yet. Core still measures SQL pages, message text and attachments. `CacheMaintenance` runs Node compaction and the rowid rebuild for old databases in `platform/node/cache-worker.mjs`. Full compaction in the portable default returns unavailable. After an abnormal exit, the desktop startup check runs a read-only quick_check in `platform/node/integrity-worker.mjs` while the main thread shows a progress window. The shared migration wrapper is `db/migrate.ts`. The Node smoke test, recovery and tests use it through `platform/node/migrations.ts`.
