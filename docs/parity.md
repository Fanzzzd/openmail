# Mimestream feature parity audit

> Maintainer notes: a feature-by-feature audit of OpenMail against Mimestream, with the evidence for each row. The README links here for the remaining gaps.

Updates from past slices are kept in git history. For current capabilities and remaining work, see this table and the [roadmap](roadmap.md).

Database migrations are append-only. The schema version equals the number of entries in `MIGRATIONS` in [db/migrations.ts](../packages/core/src/db/migrations.ts).

Code check: 2026-10-07. **284 items in total: done 251, partial 22, missing 11**. Reference material audit: 2026-09-30. We read the 54 entries of the official user guide, the FAQ, the full release history and the related release and security notes. The baseline is the macOS stable release Mimestream 1.10.8 (2026-09-04). Every behavior has an official source.

Gmail web address check: the link now uses the cached threadId (hex) instead of the messageId, and the `#all/<threadId>` compatible path stays. [Google's getPermalink docs](https://developers.google.com/apps-script/reference/gmail/gmail-thread#getpermalink) give a conversation link. The REST API docs do not guarantee a web address built by hand from an ID. We have not tested this signed out, so whether a new browser tab opens it directly is unverified.

Low-memory acceptance sets `OPENMAIL_LOW_MEMORY_TESTS=1`. The test resource config is in `packages/core/vitest.low-memory.ts`. Normal runs keep file isolation. The default real-model integration tests still need explicit opt-in.

Status definitions: done means the code has a matching product path that can be invoked. partial means only part of the behavior is covered, or only the underlying capability exists. missing means no matching implementation was found. The evidence checks UI, RPC, core and provider paths. We did not run side-by-side comparisons of Mimestream and openmail on a real machine, real account authorization, signed release or system notification acceptance. done does not mean those acceptances are complete. `none` means there is no positive implementation evidence. For missing items, the notes give the search scope and the closest implementation.

Effort is a rough estimate for closing the gap. S is a small change to an existing interface. M is a coherent implementation of a few hours for one agent. L is cross-layer work, native integration, infrastructure or external review. done rows are marked S, meaning only the existing path and acceptance need upkeep. Counts are per feature and include the settings, shortcuts and security contracts of the same capability. They are not a completion ratio or total hours.

Mimestream officially supports Gmail and Google Workspace. For Outlook, this table notes the matching behavior of openmail's personal Microsoft Graph support. Gmail success does not imply Outlook parity. Organization M365 is outside the current `consumers` authorization scope and needs admin consent; see [AGENTS.md](../AGENTS.md).

## Source coverage and limits

All Mimestream baseline sources come from mimestream.com. For this audit we opened the actual pages and did not rely on search snippets. All 54 entries in the user guide index were read, including Keyboard Shortcuts, installation and activation, accounts and Profiles, sidebar and labels, list, reading, composing and settings. The release notes were read in full back to early 0.2.x. New features were extracted and cross-checked with the current guide. Fix entries were used only to confirm that a product path still exists, and each fix is not counted again as a feature. We also read the 1.0, 1.2, 1.3, 1.5, 1.9 and 1.10 release blog posts and the 2026 system requirement and iOS beta announcements.

The official docs conflict in time. Private Push was Labs in the old 1.9 notes and is on by default in 1.10/macOS 26. Cache management changed to opt-in in a middle 1.9 release and was on by default again in 1.10.5. For sound settings, the 1.10 release notes moving them to System Settings win, so we do not rebuild a notification sound picker from the old General guide. The user guide's conversation expand key differs from the shortcut table. The list audits features and does not hardcode keys from conflicting docs.

Limits: we did not sign in to a Mimestream subscription account or TestFlight, and did not verify private betas or hidden experimental options. The public roadmap redirects to Productboard with no readable content, so roadmap cards are not treated as shipped features. We did not test the Mimestream app UI; native capabilities and version behavior come from first-hand docs. Scheduled send and read receipts, which the website does not confirm, are not added on our own. Filter editing is confirmed by the manual and a 1.5 release fix, but defining every UI detail still needs hands-on testing.
