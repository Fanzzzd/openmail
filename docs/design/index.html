openmail 设计参考

上半部分是六个邮件客户端的截图和要借的做法。下半部分是 openmail 自己的设计规格：颜色、字号、三栏宽度、键盘操作、AI 入口。截图只在本机，不进 git。

参考

每个产品只借具体做法，不照搬整体风格。右侧是要借的点和 openmail 里对应的位置。

Superhuman

键盘优先，分栏收件箱。

  • 单键处理 + Cmd+K 命令面板 面板里每条命令右边显示快捷键，用几次就记住了。
  • 主题下一行 AI 摘要 可展开，前面有 ✦ 标记，不会被当成发件人写的正文。
  • 分栏标签带计数 每个分栏由查询定义。

Shortwave

AI 面板停靠在右侧。

  • 右侧 AI 面板返回可确认的操作卡片 模型提议，用户点确认才执行。对应 MCP 写操作的人工确认。
  • 用一句话规则定义分栏 规则存成数据，模型能读也能改。
  • 按组批量清理 同类邮件归一组，一次处理整组。

Apple Mail

系统原生的密度和控件。

  • 紧凑的分类胶囊 当前分类填色并显示文字，其他只显示图标。中文标签用 14px 才看得清。
  • 会话里头像放左边 扫一眼就知道谁说了什么。

Mimestream

原生 macOS 的 Gmail 客户端，最接近 openmail 的定位。

  • 会话堆叠折叠，只展开最新一封 旧邮件折成一行：头像、发件人、首句。点开再展开。

HEY

新发件人先过筛选。

  • 新发件人逐个决定 每个发件人只问一次：放进收件箱，还是挡掉。

Spark

分组收件箱，公开了给 agent 用的 CLI。

  • 分组区块带「显示全部（n）」 每组默认只露几封，数字说明还剩多少。
  • 新发件人筛选 和 HEY 同一个思路。
  • 给 agent 用的 CLI 和 API openmail 已经有 CLI 和 MCP，方向一致。

Notion Mail

2026-09-22 关停。只作反面参考，不当模板。

openmail 规格

布局以 Mimestream 为准：侧栏顶部是账户磁贴，列表不放头像，会话堆叠、头像在左。系统字体，浅灰侧栏，白色列表和阅读区。唯一的品牌元素是航空信封的红蓝斜纹，只用在本页顶部和 app 的关于页。

字号

一套系统字体：SF Pro 加苹方。中文在 13px 以下笔画会糊，所以中文标签最小 14px，13px 只给列表行和时间这类以数字、英文为主的文字。

键盘

列表是焦点时，单键直接生效，不需要修饰键。写操作的快捷键等 Gmail scope 升到 gmail.modify 之后再接上。

列表和选中态

键盘移动的选中行用实心 accent 加白字。鼠标点中的行用中性灰，不抢眼。未读是左侧蓝点加粗体发件人。AI 摘要在主题下一行，紫色，带 ✦。

AI 面板

把这周的新闻订阅都归档

归档 18 封新闻订阅

来自 6 个发件人，都在「新闻订阅」分栏，9 月 22 日到 28 日。

AI 入口规则

  1. AI 写出的文字只出现在两个地方：列表行的摘要和右侧 AI 面板。两处都用紫色和 ✦，不和邮件原文混排。
  2. 模型只提议。每个改动邮件的动作变成一张操作卡片，按钮写明动作和数量，用户点了才执行。
  3. 分栏由查询或一句话规则定义，存在数据库里。模型可以通过 MCP 读和改规则，改完在面板里显示差异，由用户确认。
  4. 新发件人进「新发件人」分栏，每个发件人问一次：放进收件箱，还是挡掉。
  5. 模型的每次写操作记审计日志，面板里能查。
