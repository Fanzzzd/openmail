# Desktop accessibility

The automated renderer checks cover component semantics, keyboard operation, announced content and theme color values. The tests do not start Electron, and they do not stand in for real VoiceOver acceptance.

The keyboard tests check Tab cycling, Escape to close and focus return in dialogs and pickers, opening and closing menus by keyboard, arrow keys in the format bar, and Delete to remove a recipient. Shift+F10 on a message row opens the full action menu, which gives keyboard access to the swipe and mouse actions.

A message row's name reads only the sender, subject, time, and unread and starred state. `aria-selected` provides the selection state. The reader's polite region reads the sender and subject of the selected message, and a message text refresh does not trigger a repeat announcement. Recipient removal, undo prompts, and sync failures starting and recovering use stable live regions. Sync time and progress changes are not announced. `aria-describedby` links form validation errors, and send errors also show an alert.

HTML messages keep the script-free iframe sandbox and the default resource CSP. Message text uses `dir="auto"`. The HTML iframe uses the UI locale as its `lang` and has its own focus and reduced motion rules. The link confirmation focuses "Cancel" by default and returns focus to the original link when it closes.

## Known gaps

- jsdom has no layout or painting, so axe's `color-contrast` rule is off. The color value checks verify the listed theme combinations. They cannot prove contrast for arbitrary mail HTML, images, transparent overlays and all dynamic backgrounds.
- Electron and real VoiceOver have not been run. Someone needs to confirm on macOS the browse order of the virtual list, focus return after a link confirmation inside the iframe, the speech after removing a recipient, and the announcement pacing during repeated actions.
- Mail has no reliable language metadata. For now the HTML iframe inherits the UI locale as its language, so messages in other languages may still need the user to switch pronunciation. Automatic direction follows the first strong directional character. Mixed-direction mail and the author's own styles need manual checks.
- In arbitrary mail HTML, the sender supplies the headings, tables, image alt text and colors, and the component fixtures do not cover them. axe checks the heading levels inside the app frame.
- The composer currently offers "Send", "Send and archive" when replying, and the send confirmation dialog. It has no separate send dropdown menu. The attachment menu and send confirmation are both covered.

Build before running the full checks, because the theme test reads the build output. Run the check commands in [AGENTS.md](../AGENTS.md) and set `OPENMAIL_LOW_MEMORY_TESTS=1` for the tests.
