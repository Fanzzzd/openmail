# 桌面安全

邮件 HTML、附件、链接、启动输入和 IPC 参数均不可信。保护目标是阻止邮件执行代码、读取本机文件、调用主进程或窃取 OAuth token、AI key。已控制操作系统或替换开发源码的攻击者不在此边界内。依据：[Electron 安全清单](https://www.electronjs.org/docs/latest/tutorial/security)。

refresh token、IMAP 密码和 AI key 仅持久化于 core 的 `platform/node/secrets.ts` 系统钥匙串。renderer 仅获取配置状态；输入中的 key 临时经 IPC 保存，不写浏览器存储。浏览器存储仅保存界面设置，应用无复制凭据接口，主窗口和撰写窗口标题固定为 OpenMail；thread/message 使用去控制字符、最多 200 字符的主题。`main/index.ts` 的文件 logger 不记录原始错误；启动失败的 `Cause.pretty` 仅输出到 stderr；core `platform/node/diagnostics.ts` 在写入和导出时限制字段，账户只保留散列。未启用 crashReporter，并设置 disable-breakpad；系统自行生成的内存转储由操作系统策略管理。联系人和通知设置的系统协议由主进程固定构造，邮件不能指定。

`electron-builder.config.cjs` 的 afterPack 调用 `build/security-fuses.cjs`，签名前关闭 RunAsNode、NODE_OPTIONS、CLI inspect、file 额外权限；开启 CookieEncryption、ASAR 完整性、OnlyLoadAppFromAsar。完整性依赖正式包的 ASAR 元数据和签名。参见 [fuses 文档](https://www.electronjs.org/docs/latest/tutorial/fuses)。

macOS 启用 hardened runtime。`build/entitlements*.plist` 仅声明：

- `allow-jit`：Electron/V8 主进程及 helper 所需。
- `personal-information.addressbook`：可选本机联系人功能，应用和 contacts helper 声明，其他继承 helper 不授予。
- `disable-library-validation`：仅未签名构建，用于无团队签名的原生依赖；正式签名配置不含此例外。推理使用 Electron 的专用 Plugin utility process，见 `main/inference.ts`。
- contacts helper 仅有 addressbook，无摄像头、麦克风、定位、Apple Events 或全磁盘权限。

验证：`security.test.ts`、`rpc-security.test.ts`、`files-security.test.ts` 及现有窗口、iframe、诊断和钥匙串测试；读取构建后的 HTML、preload、JS。fuses 测试修改临时模拟二进制的真实 fuse wire，不修改已安装的 Electron。使用 `OPENMAIL_LOW_MEMORY_TESTS=1`。本次未启动 Electron、未生成签名安装包；运行时及正式签名仍需发布流程验证。

CookieEncryption 在 macOS 使用系统钥匙串。ad-hoc 签名的本地包或重签名后首次启动可能弹出 Chromium cookie 加密密钥访问提示，反复重建也可能再次询问。这与 OpenMail 的 OAuth/API key 钥匙串项不同；不为消除提示关闭 fuse，因为关闭后已有 cookie 存储可能无法使用。参见 [Electron cookieEncryption](https://www.electronjs.org/docs/latest/tutorial/fuses#cookieencryption)。

frame 标识依据：[Electron WebFrameMain](https://www.electronjs.org/docs/latest/api/web-frame-main#frameframetreenodeid) 及已安装 Electron 44 类型定义。frameTreeNodeId 在浏览器内唯一，生命周期内固定。

## 邮件内容保护

- 模型上下文和文本向量读取与阅读器共用资源处理后的 HTML，以 htmlparser2 遍历可见文本。删除隐藏属性、隐藏 CSS、透明度或 alpha ≤ 0.1、缩放 ≤ 0.1、极小字体、单位对应的负偏移、裁剪及近似同色文本；忽略 title、SVG desc、媒体后备文本、datalist 和 details 摘要之外的内容。color-string 解析完整 CSS 命名颜色、HSL、百分比 RGB 和 4／8 位 hex，背景简写提取颜色并按 alpha 合成；样式表选择器由 css-select 匹配。HTML 优先于 plain alternative，差异明显时返回 `plain-differs`，删除隐藏文本时返回 `hidden-text-removed`。CSS 检查预算耗尽时返回 `budget-exceeded`，并以固定占位文本 `[Message too complex for AI: message text omitted.]` 省略消息文本，不回退到未经完整可见性判断的 HTML 或 plain alternative。摘要与回答继续作为纯文本显示，URL 和电话不会自动变成链接。实现：[visible-text.ts](../packages/core/src/visible-text.ts)、[model-view.ts](../packages/core/src/model-view.ts)、[semantic-indexer.ts](../packages/core/src/semantic-indexer.ts)；输出：`AiPanel.tsx`。MCP 列表和搜索不返回 provider snippet，防止预览携带不可见或不同的文本。所有外发工具结果的邮件派生字段统一放入 `untrusted_mail`，并带固定 `notice`。引用移除识别 In-Reply-To、匹配的 `>` 引用、`On … wrote:`，以及完整的 From/Sent/To/Subject 回复头块；后两种不依赖缓存邮件头。无可靠边界时移除 `>` 行会返回 `quoted-text-removed` 和字符数。
- 认证结果只考虑按收到顺序排列的最上一个 Authentication-Results，低位头不能建立或覆盖信任。Gmail 要求 authserv-id 为 `mx.google.com`。IMAP 默认 unknown；用户可在每账户设置显式填写管理员提供的 authserv-id，必须与最上一个头匹配，IMAP host／预设不代表信任。变更该设置会清空该账户的缓存认证结果。Microsoft 格式没有 authserv-id：原始头解析仅接受格式以 spf/dkim/dmarc 开始，首个 Received 的接收方为 `*.outlook.com`，且认证头位于首个接收 hop 的头块内（第二个 Received 之前，可在首个 Received 上方或后方）；其他顺序均 unknown。当前 Graph 的认证结果固定为 unknown：delta `$select` 不含 `internetMessageHeaders`；普通消息 GET 仍取邮件头供本地搜索使用，但不依据其顺序建立认证信任。因此 Outlook 不启用认证相关的自动图片或一键 POST。AR 先移除嵌套注释与引用字符串，再按顶层分号解析，每种方法取最后一次结果。迁移 32 存储 DMARC/SPF/DKIM 与安全退订目标；旧缓存缺少结果时仍为 unknown。发件人名称去除 Unicode Cf 字符，阅读器始终显示地址，DMARC 失败和名称夹带其他地址均告警。长期图片许可仅在可信 DMARC pass 时生效，否则逐封加载。Reading 设置的远程图片默认询问；“来自我认识的人”只对服务端联系人、桌面开启的 Apple 通讯录、本账户或发过邮件的地址生效，且同样要求 DMARC pass，因此 Outlook 和未配置可信 authserv-id 的 IMAP 不会自动加载；“总是”加载所有邮件。core `shouldLoadRemote` 统一判断，桌面和手机共用。“加载图片”只放行点击时显示的消息，之后加入会话的消息仍会询问。已知跟踪器和 1×1 像素在任何模式下都移除。cid 内嵌图片来自缓存原文或服务商，始终显示，不触发提示。IMAP 管理者须确保服务器剥除外来同名认证头。实现：[message-security.ts](../packages/core/src/message-security.ts)、[Gmail](../packages/core/src/gmail.ts)、[Outlook](../packages/core/src/outlook.ts)、[Node IMAP](../packages/core/src/platform/node/imap.ts)、[store.ts](../packages/core/src/store.ts)；`Reader.tsx`、`AccountControls.tsx`。
- 邮件打开链接默认去掉 `utm_*`、fbclid、gclid、mc_eid、mc_cid，可在 Reading 设置关闭。仅删除原始 query 中对应的段，保留其余字节编码；存在 `X-Amz-*`、Signature／sig／signature、token、hmac、Expires、Key-Pair-Id 或 Policy 时完全跳过清理。浏览器的 popup 出口始终拒绝，无法跳过阅读器确认。邮件 mailto 不交给 shell，发送仍须人工审阅。域名比较使用注册域并包含私有后缀；实现见 [link-security.ts](../packages/core/src/link-security.ts)和 [email-links.ts](../apps/desktop/src/renderer/src/components/email-links.ts)。
- 可执行文件、磁盘映像、宏文档、系统导入及活动文档扩展不交给 native open/preview/openWith/share/copy/drag；保存仍允许。HTML/SVG 的打开与预览走无脚本、禁远程资源的 EmailFrame。ICS/VCF 进入应用内预览，添加联系人或日历事件须单独点击；iTIP 邀请仍走回应流程。IMAP 无日历写权限，只读会话禁止日历导入写入，联系人导入沿用 macOS Contacts 支持。实现：`main/attachment-filenames.ts`、`attachment-actions.ts`、`files.ts`、`AttachmentImportDialog.tsx`；core `attachment-import.ts`。
- 所有 provider 都显示 organizer 与 MIME From 不同的邀请警告，Sender 头不能压过真实 From。未知 agent surface 或不在该 surface 操作清单内的命令默认拒绝。实现：core `invites.ts`、`policy.ts`；`InviteBanner.tsx`。
- 退订先显示目标并确认。仅当可信 provider 的 DKIM pass 通过 d（或 i 的域）/s/b 唯一对应一条签名、d 与 From 的注册域对齐、且 h 覆盖 From 和两个唯一的 List-Unsubscribe 头时，才启用 RFC 8058 HTTPS POST。认证元数据缺失、签名歧义或覆盖不足时仅允许 mailto 经撰写确认；没有安全路径则不显示退订按钮。Node adapter 解析并固定公共 DNS 地址，只发 `List-Unsubscribe=One-Click`，无 cookie、Authorization 或重定向，也不 GET 任意退订 URL。只读会话禁止 POST；其他平台未提供 POST adapter 时拒绝执行。实现：core `message-security.ts`、`unsubscribe.ts`、`platform/node/unsubscribe.ts`；`UnsubscribeButton.tsx`。协议依据：[RFC 8058](https://www.rfc-editor.org/rfc/rfc8058)。

可见文本提取采用保守静态 CSS 判断，不运行浏览器布局或外部样式表；不能证明任意 CSS 都与实际像素一致。回归包含 Gmail／Microsoft／Fastmail 格式、顶层失败与低位伪造通过、AR 注释／引用注入、IMAP 信任保存与撤销、MCP snippet 删除、CSS 隐藏方式、Unicode／嵌入式链接标签和签名 query 保留，以及先前的 DKIM、退订、附件和 agent policy 样例。未启动 Electron，也未对真实邮件服务执行退订。

## 服务商诊断

桌面在 `OPENMAIL_HOME/diagnostics/diagnostics.jsonl` 记录固定字段，默认数据目录见 [README](../README.md#cli-与-mcp)。Gmail／Graph 的 `provider-failure` 只保存时间、服务商、HTTP 方法、端点模板、可用的 status、failure 分类和账户 ID 的 16 位 SHA-256 前缀。搜索失败还保存 operation=search 和固定枚举的 Graph error.code，未知代码保存 unknown；延期不写事件。不保存完整 URL、query、资源 ID、消息文本、错误正文、堆栈或 token。该格式不提供 IMAP 协议逐条日志，也不证明散列匿名化。

`failure` 分为 `http`、`transport`、`credentials`、`configuration`、`other`。只有实际传输失败用 status 0；缺少 OAuth client 属于 configuration，无 HTTP 状态。凭证失败与局部服务权限不足分别处理，可选端点的权限 403 在重新登录前停止重复请求，不暂停正常邮件同步；限流或未启用 API 不按此规则缓存。

`sync-reset` 诊断还记录服务商、listing／reset／verification 阶段、账户与文件夹哈希，以及列出、保留、候选、已验证和延期等计数，不记录候选 ID。runtime-error 的 sync-crashed 还允许固定 phase 和 causeKind，不导出异常内容或堆栈。RPC renderer 回调显式返回 void，防止 Fiber 经 contextBridge 返回时触发克隆错误；回归用 structuredClone 检查 JSON 帧和回调返回值。事件定义见 [sync-reset.ts](../packages/core/src/sync-reset.ts)，落盘与导出沿用同一字段白名单。

每文件默认 256 KiB，另保留最多三份轮转档。Feedback 展示导出预览并让用户选择附件，创建反馈草稿不自动上传；旧日志在预览时重新按白名单编码。RPC 失败仅记录方法名，不记录参数，正常中断不记录。实现见 [provider-diagnostics.ts](../packages/core/src/provider-diagnostics.ts)、[diagnostics.ts](../packages/core/src/platform/node/diagnostics.ts)、[reliability.ts](../apps/desktop/src/main/reliability.ts)和 [Feedback.tsx](../apps/desktop/src/renderer/src/components/Feedback.tsx)，回归见 [provider-diagnostics.test.ts](../packages/core/src/provider-diagnostics.test.ts)。

只读会话的范围只在[架构](architecture.md#只读会话)维护；smoke 的原始 console 和 stderr 不是上述脱敏日志。解析器 fuzz 与无障碍测试的运行方式和限制只在[测试](testing.md#解析器-fuzz-与无障碍)维护。
